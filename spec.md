# Spec — Завдання 3: тестування VV Audio

## Намір

щоб усі слухали одне й те саме, і обов'язковим правилом було те, що преміум користувач не міг обійти чергу

## Критична логіка

не обгааняти чужаі преміум треки які закинули раніше і взагалі не ставитиме більше двох преміум треків поспіль
захист від рейсів кандишиноа та дублів
повтор запиту индепотенси кей не повинен створювати дубль
власник управляет румой i решает какие запросы принимать

## Рiвнi тестiв

### Unit

queue.service там все мейн правила аппки добавление треков и порядок очереди премиум приоритеты права
покриття 100% гілок + мутанти вбиті чи клаaсифікованi

### Інтеграційні

POST /api/rooms/:code/playback/ended, 10 одночасних зсув рівно на 1 трек за кодом усі отримують 200 статус
поавтор с тем же idempotency-ket верне 201, в черзi 1 трек

### E2E

другий користувач заходить за кодом і бачить ту ж кімнату черга поточний трек та стан відтворення що і перший

### Мутаційне

модулі queue.service idempotency access playback.service
поріiг mutation score не менше 80% по кожному модулю, 100% не вимагаємо тощ частина мутантів може бути еквівалентною
команда npm run test:mutation
звіт хтмл у reports/mutation/ + таблиця тих, хто вижив у markdown
хто вижив отримує клас реальна прогалина доданий тест який його вбиває / еквівалентний / прийнятний, і коротко чому

## Критерії прийняття

server/services/queue.service.ts — покриття гілок 100% перевіряється npm test пада якщо меньш 100%

server/services/access, server/services/idempotency, server/services/playback.service - покриття гілок ≥ 80 перевiрка npm test пада якщо меньш 80%

премиум 2 трека пiдряд можна 3 вже вертае 409 статус - npm run test

преміум користувач піднімає свій трек чужий преміумтрек доданий раніше не можна обігнати — 409 статус свій трек можна підняти — unit, npm test

людина не перебуваає в кімнаті і намагається відкрити її або додати трек - вертае 403 - npm run test:integration

звичайний учасник тисне плей некст - вертае 403 - npm run test:integration

учасник намагається видалити чужий трек безпосередньо - вертае 403 - npm run test:integration

10 одночасних запитів playback/ended для одного поточного треку - усі відповіді 200, черга зсувається на 1 трек, поточний стає наступним, попередній трек зараховано зіграним 1 раз — npm run test:integration

2 однакових запити з одним idempotency-ket - обидва повертають 201 з однаковим тілом, у черзі 1 трек — npm run test:integration

перший юзер создав руму додав трек в стек и нажав плей другий користувач заходить у кімнату за кодом - бачить ту саму кімнату чергу поточний трек і стан відтвореннящо й перший користувач — npm run test:e2e

мутації для queue.service access idempotency та playback - mutation score ≥80% для кожного модуля хтмл-звіт у reports/mutation/ усі мутанти що виижили маювть клас і коротке пояснення — npm run test:mutation

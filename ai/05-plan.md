# 05 — План реалізації (вихід AI, на погодження студенту)

Стек (рішення студента): Fastify, PostgreSQL (Docker, нестандартний порт), Kysely + Kysely Migrator,
AsyncLocalStorage, один глобальний обробник помилок, Socket.IO лише для розсилки оновлень.

## Етапи (кожен — окремі коміти)

1. **spec.md + ADR** — пише студент.
2. **Каркас Fastify:** контекст AsyncLocalStorage (business-process ID, користувач, транзакція), логер із ID у кожному рядку,
   типізовані помилки + `setErrorHandler`, `/version`, `/healthz`.
3. **Статичний прототип:** інтерфейси репозиторіїв + in-memory реалізації + статичні дані
   (користувачі, зокрема преміум і адмін; кімнати, зокрема від 5 учасників; треки);
   сервіси з бізнес-правилами й доступами; REST-роути на всі сценарії; Socket.IO-розсилка;
   `npm run scenarios` — прогін усіх сценаріїв через HTTP.
4. **PostgreSQL:** docker compose (порт 55432), міграції структури окремо від seed,
   пул з явною ініціалізацією + `SELECT now()` на старті (падати одразу), Postgres-репозиторії,
   транзакції через AsyncLocalStorage, окрема база на тестовий прогін.
5. **Збої та ідемпотентність:** ретраї oEmbed, ізоляція збоїв провайдерів пошуку, поведінка при недоступній БД,
   ідемпотентність (див. нижче).
6. **Мінімальний UI** на новому API: кімнати, ролі, запити на видалення, позначка преміум, пошук.
7. **Аудит:** N+1 (знайти й виправити), поведінка на збоях, топ-3 зрізаних кутів → матеріал для DEFENSE.

## Ідемпотентність (п.4 — обговорити)

Варіанти:
1. Заголовок `Idempotency-Key` на створюючих запитах; ключ зберігається в тій самій транзакції, що й результат;
   повтор → той самий збережений відповідь; той самий ключ з іншим тілом → 422.
2. Природна ідемпотентність: PUT/DELETE (ролі, обране), унікальні обмеження (один відкритий запит на видалення
   від користувача на трек → повернути наявний), переходи станів лише один раз (pending → approved).
3. Умовні операції: `next` / «трек закінчився» передають ID поточного треку й виконуються лише якщо він ще поточний
   (інакше подвійний skip пропустить два треки).

Пропозиція AI: 1 — для створення треку, повідомлення чату, кімнати; 2 і 3 — для решти.

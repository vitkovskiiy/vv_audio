# ADR 0001: Вибір бази даних

- **Статус:** accepted
- **Дата:** 28.10.2026
- **Автор:** Iван Вiтковський

## Контекст

Яку проблему розв'язуємо? 2–4 речення.
що зараз скллайт у файлі data/vv.db, у процесі застосунку
які сценарії навантажують бд кімнати, черга з пріоритетом, ролі, запити на видалення, чат
що вимагають наступні лаби лаба 4: міграції без простою blue-green два екземпляри застосунку одночасно
лаба 5: EXPLAIN ANALYZE, індекси, пул зєднань

## Чинники рішення

окремий серверний процес, до якого підключаються кілька екземплярів застосунку
транзакції й надійність при втраті живлення
інструменти аналізу запитів
простота локального запуску

## Розглянуті варіанти

1. PostgreSQL
2. SQLite
3. MariaDB

## Рішення

Обрано **PostgreSQL**, тому що postgres це в подальшому вiн легко деплоiтьчя пiд блю-грин
Вiн мае окремий процес це те що нам i було потрiбно що sqllite нам дати не може
доступ до бдKysely SQL видно як є, типи перевіряються, транзакції легко класти в AsyncLocalStorage (ai/03)

## Плюси та мінуси варіантів

### PostgreSQL

- **+** потужний функционал
- **+** добре масштабуетсья
- **−** бiльш хевiвейт чем скллайт i марiадб

### SQLite

- **+** легкий
- **−** блокуе базу пiд часу запису

### MariaDB

- **+** теж швидкий те що це форк майскл
- **−**• поступається постгресу у можливостях аналітики, кастомних функцій та обробки нереляційних структур

## Наслідки

потрібен Docker для локального запуску; порт не 5432ізольоване середовище
міграції замість CREATE TABLE IF NOT EXISTS пул з'єднань і перевірка SELECT now() на старті
перенесення наявних даних із скллайт або свідома відмова від цього

# VV Audio

Кімната для спільного прослуховування музики з друзями: одна черга, одне відтворення в усіх одночасно. SoundCloud, YouTube і Spotify, без Spotify Premium.

## Запуск

Потрібні Node.js 20+ і Docker.

```
npm install
npm run db:up        # PostgreSQL 18 у Docker на порту 55432
npm run db:migrate   # структура БД (окремий крок, не на старті сервера)
npm run db:seed      # статичні дані: кімнати PARTY5 (8 людей) і CHILL2
npm run dev          # API на :3001 + клієнт на http://localhost:5173
```

Скопіюйте `.env.example` у `.env`. Для PostgreSQL потрібні рядки:

```
STORAGE=postgres
DATABASE_URL=postgres://vv:vv@localhost:55432/vv
```

Без `STORAGE=postgres` сервер працює на статичних даних у пам'яті (прототип), нічого ставити не треба.
Тестові акаунти з seed: `vika` (власниця PARTY5, безкоштовний план), `borya` і `dana` (преміум), `admin`; пароль у всіх `password123` — лише для розробки.

## Ролі та правила

| Дія                                      | Власник кімнати | Учасник                               |
| ---------------------------------------- | --------------- | ------------------------------------- |
| Додати трек                              | ✓               | ✓                                     |
| Play / pause / перемотування / наступний | ✓               | запит власнику на пропуск             |
| Прибрати трек                            | будь-який       | свій — одразу; чужий — запит власнику |
| «Грати наступним»                        | ✓               | —                                     |
| Вирішити запит                           | ✓               | —                                     |
| Видалити кімнату                         | ✓               | —                                     |

- **Преміум** (властивість акаунта, видає адмін через `PUT /api/admin/users/:username/plan`): піднімає свої треки в черзі, але не вище раніше поставленого преміум-треку іншого користувача і не більше двох преміум-треків поспіль. Якщо власник кімнати теж преміум, його «грати наступним» обігнати не можна.
- **Безкоштовний план:** до 5 власних кімнат; шоста → вікно «Є кімната, де тусовка вже закінчилась?» з видаленням.
- Реальні платежі поза обсягом.

## Перевірка

```
npm test                # unit-тести: контекст і bpId, глобальний обробник помилок, відкат транзакції
npm run scenarios       # усі сценарії через HTTP на статичних даних (55 перевірок)
npm run scenarios:pg    # ті самі сценарії на PostgreSQL + збої БД і кількість SQL (63 перевірки)
```

Кожна перевірка підписана критерієм (K1…K18) з `ai/09`–`ai/11`. `scenarios:pg` створює окрему тимчасову базу на прогін і видаляє її в кінці; збій БД імітується TCP-проксі, спільний контейнер не зупиняється.

`GET /version` повертає SHA коміту, `GET /healthz` — стан БД (503, якщо недоступна).

### Якість коду

```
npm run lint            # ESLint з перевірками за типами (typescript-eslint)
npm run format          # Prettier
npm run smoke           # швидкий smoke-тест справжнього сервера без БД і мережі
npm run check           # format:check → lint → typecheck → test → smoke → build
```

Git-хуки (husky, ставляться під час `npm install`): `pre-commit` — Prettier і ESLint лише на змінених файлах; `pre-push` — повний `npm run check`.
TypeScript закріплено на 6.0: typescript-eslint поки не підтримує TypeScript 7.

## Архітектура

```
server/
  routes/        HTTP: схеми валідації, статуси; бізнес-логіки немає
  services/      бізнес-операції та доступи
  repositories/  ports.ts — інтерфейси; memory.ts — статика; postgres.ts — Kysely (SQL і транзакції лише тут)
  db/            міграції (0001 структура, 0002 індекси) і CLI migrate / seed
  context.ts     AsyncLocalStorage: bpId, користувач, логер запиту
  container.ts   ресурси процесу (репозиторії, джерела метаданих, пошук), ініціалізуються на старті
  app.ts         Fastify + один глобальний обробник помилок
  realtime.ts    Socket.IO лише сповіщає «кімната змінилась», стан клієнт читає по HTTP
client/          React + Vite; плеєри YouTube / SoundCloud / Spotify через офіційні вбудовані плеєри
```

Кожен рядок логу запиту містить `bpId`; він же повертається в заголовку `x-bp-id` і в тілі будь-якої помилки `{ error: { code, message, bpId } }`.

## Пошук за назвою

Скопіюйте `.env.example` у `.env` і впишіть ключі, які маєте. Джерело без ключа просто не бере участі в пошуку; додавання за посиланням працює завжди.

| Джерело    | Що потрібно                                                              | Ціна                                               |
| ---------- | ------------------------------------------------------------------------ | -------------------------------------------------- |
| YouTube    | `YOUTUBE_API_KEY` (Google Cloud Console → YouTube Data API v3 → API key) | безкоштовно, ~100 пошуків на день                  |
| SoundCloud | `SOUNDCLOUD_CLIENT_ID`, `SOUNDCLOUD_CLIENT_SECRET`                       | за документацією SoundCloud потрібен Artist Pro    |
| Spotify    | `SPOTIFY_CLIENT_ID`, `SPOTIFY_CLIENT_SECRET`                             | з лютого 2026 власнику застосунку потрібен Premium |

`SOURCES=static` вмикає статичні назви й результати пошуку без мережі (для прототипу та перевірок).

## Як покликати друга з інтернету

1. `npm run build`, потім `npm start` — сервер віддає і API, і зібраний клієнт на :3001.
2. Тунель на цей порт: `cloudflared tunnel --url http://localhost:3001` або `ngrok http 3001`.
3. Відкрийте кімнату за адресою тунелю й скопіюйте посилання кнопкою «Покликати друга».

## Відомі обмеження

- Завантаження власних аудіо/відео-файлів поки вимкнене: старий ендпоінт прибрано разом з Express, новий ще не зроблено.
- Spotify у вбудованому плеєрі грає повний трек лише слухачам, які увійшли в Spotify у цьому браузері; інакше — 30-секундне прев'ю.
- Обмеження «не більше двох преміум поспіль» діє на ручне переміщення; нові треки стають у кінець черги.
